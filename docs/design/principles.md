# Fractal design principles

Fractal should read like a well-set journal, not like a dashboard generated by a tool. The paper is the subject; the interface is typesetting around it.

## Principles

1. **The paper leads.** Screens exist to get a reader into a paper and keep them there. Controls appear where they are used (a selection menu, a button beside a figure) and stay out of the way otherwise.
2. **Hairlines, not boxes.** Group with space and thin rules. A heavy rule (2px ink) opens a page section, a hairline separates items. No cards around content.
3. **Hierarchy through type.** Paper titles and screen titles are set in the serif; everything else is Pretendard. Weight and size make the order clear, so labels and helper text are rarely needed.
4. **One accent.** Proofreader's red (`accent`) marks what needs attention or is actionable text. Everything else is ink on paper. No gradients, glows, or coloured status pills.
5. **Design that does not explain itself.** If a screen needs a sentence to say how to use it, fix the screen. The single input shows what Enter will do; empty states get one sentence at most.
6. **The metaphor is structure, not decoration.** A fractal repeats one shape at every scale: field → paper → section → paragraph use the same list grammar, and citations branch from the paper. The mark is the only literal fractal.
7. **Keyboard first on desktop, pen first on tablet.** Every command is in the palette (Ctrl/⌘+K). On Android the pen writes and the finger scrolls.

## Things we do not do

These are the patterns that make an interface look machine-made (the old PaperRead UI had most of them):

- rounded bordered cards around every block;
- numbered 1-2-3 step cards and onboarding checklists;
- tiny eyebrow labels over every heading;
- explanatory helper sentences under controls;
- green-dot status pills ("연결됨 ●");
- suggested-prompt chips;
- a row of same-weight bordered buttons with no primary action;
- letter-tile logos, sparkle icons for AI, purple gradients, "AI가 답변 중…" theatre.

## Tokens

`packages/shared/tokens/tokens.json` is the single source. `npm run tokens` generates:

- `packages/ui/src/design/tokens.css` — CSS custom properties; `:root` is light, `[data-theme='dark' | 'sepia']` override, and with no attribute the system scheme decides;
- `packages/shared/tokens/generated/FractalTokens.kt` — Compose colours, type sizes, spacing and radii for Android.

## Shell

- **Masthead**: mark + wordmark, 홈 · 보관함 · 설정, the single input, the palette key, and the account state in words. Below 860px it becomes two rows so the input keeps the full width.
- **Single input**: arXiv id or link, DOI or doi.org link, any paper URL, or words (library search). A PDF can be chosen from the input or dropped anywhere on the window.
- **Screens** are addressed by hash (`#/library`, `#/settings`) so back/forward works in the desktop window.
