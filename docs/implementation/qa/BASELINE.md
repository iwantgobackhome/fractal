## High-risk reproduction cards

### History routes (requests 2/6)

Run `npx tsx docs/implementation/qa/baseline-probe.ts` after `npm run build`. It creates a temporary SQLite directory and fixture provider, consumes successful `/ask` and `/explain` route streams, closes/reopens the store, and records zero conversation rows. It then uses ordinary ChatService and reopens again: both ordinary messages persist. No account or external provider is used. This executes real route handlers directly, not HTTP authentication or the explanation card click.

On a device: ask a question, close compact bottom sheet or switch paper, then reopen. Baseline SidePanel answer is `remember` state; no history fetch exists. On desktop: explain a marked figure, close card, revisit figure; App clears text and starts another generation. Required replacement must retain completed/failed/cancelled entries and quote/page context across panel close, process restart, and device recreation.

Language/theme preferences have durable local storage and Hub settings paths (`shell/preferences.ts:37`, `53`; `shell/theme.ts:41`; Android `MainActivity.kt:90`, `AppLanguage.kt:13`). However preferences optimistically save locally and swallow failed Hub writes (`preferences.ts:74`), while next load prefers the older Hub record. Reproduce with isolated Hub write failure, change language, restore network/reload; verify acknowledged/error state and retry rather than silent rollback. Reader zoom/split/page and Android scroll/answer use in-memory state, so their restart behavior is not covered by the existing smoke.

### Memo presentation and context loss (requests 6/10/11)

Source reproduction: Android memo JSON `{kind:'memo',text:'My observation',quote:'Selected sentence',page:2,rect:...}` renders the selected sentence but never My observation. With quote empty, it renders Selected region, still never the memo body. Legacy memo without quote uses text as quote; a fix must avoid confusing body with quote or duplicating it. Highlight `{kind:'highlight',text:'Quote',note:'Body'}` is a different shape and currently renders both.

Android Selection → Questions clears selected and only opens panel (`ReaderScreen.kt:321`). SidePanel builds `{question,answerLanguage,selection}` at `149`, omitting selectedText/page/rect. Capture request in isolated paired device test to prove replacement propagates the selected text and physical page exactly once and clears it on cancel/paper switch. `SidePanel.kt:172` consumes only delta/done, ignoring SSE error; a 200 stream ending with error may leave blank/partial answer with no actionable error. Treat network/HTTP errors and SSE errors as separate gates.

### Cursor race (requests 2/3/6/11 persistence)

Source-confirmed interleaving, not executed Room/device reproduction: Android pulls to cursor 10 and applies it (`SyncEngine.kt:30`, `64`). Another device writes memo at seq11. Android pushes its dirty annotation; server returns current global cursor, e.g.12, without returning intervening changes (`packages/hub/src/api/routes/sync.ts:15`). Android saves that cursor (`SyncEngine.kt:92–95`), then next pull since12 omits the remote memo at11 indefinitely. `sqlite.ts:577` pulls only changes after since. The cursor must represent consumed pull data; push acknowledgement alone cannot prove consumption. B owns contract/server semantics and D owns cursor adoption. Required targeted verification controls pull/push interleaving, including remote edit/delete, local dirty records, and restart, with no data skip. Existing MergeRules tests cover ordering, not this network interleaving.

### Selection precision and compatibility (request 10)

Probe logs a drag x15→35 within a text run spanning x10→310; result is full run and full quote. Current Edge smoke proves a drag creates a highlight, not exact word boundaries, multi-column selection or mathematical glyph correctness. On Android API35, long-press a word then drag to extend: source has no drag extension route. On API29–34, native selection returns null, fallback has empty text, and Copy currently copies an empty string. Scanned/image-only PDFs also need an explicit region/unsupported state; do not describe region selection as extracted text.

### Header/ink geometry (request 8)

Device recipe: fit-width multipage PDF, scroll to middle of page, record page top and a known printed word, tap/write/lift pen repeatedly, then finger-scroll up/down. Log header measured height, lazy-list index/offset, page transform and ink anchor before/during/after. Baseline 48→12dp hidden-spacer change and .72→actual aspect are code risks. The fixed header/overlay design must keep the printed word stable within 2dp during pen contact/release without actual scrolling; evaluate first bitmap load separately. Only a physical pen run can establish tool classification, palm rejection, pressure, button eraser and latency.

### Related loading and stale data (request 13)

Use controllable source responses: S2 429 + OpenAlex success; both429; S2 429 + OpenAlex empty; timeout; expired cache + failure; no identifier; retry. Existing test covers the first three. UI recipe: begin delayed request for paper A, switch to B, let B finish first, then A. `RelatedPanel.load` has no epoch/abort/cleanup, so an older resolution can set current component state; App renders it without a paper key (`App.tsx:1716`). This is a source-confirmed race risk; verify actual mounting behavior during integration. Preserve paper identity and display cached/stale/source facts instead of presenting wrong-paper results or an unexplained spinner.
