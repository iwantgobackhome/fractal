## Diagnosis and correction

Read-only inspection of cached AGP 8.9.1, common 31.9.1 and sdk-common 31.9.1 bytecode confirms that the default debug keystore comes from AndroidLocationsProvider's preference directory. Its selection honors ANDROID_USER_HOME/ANDROID_PREFS_ROOT/ANDROID_SDK_HOME, then TEST_TMPDIR/XDG_CONFIG_HOME/Java user.home/HOME. The restore script previously wrote Node's home directory plus `.android`, ignoring those overrides. The CI log does not record the resolved Gradle signing-store path, so a particular runner override remains an inference rather than a proven historical fact. Independent QA confirmed the same resolver order; the coordinator separately reconfirmed the original local key's public certificate.

The workflow now passes the same absolute `runner.temp/fractal-android-signing/debug.keystore` path explicitly to key restoration and the Android build. The restore script refuses missing expected-certificate configuration, exports only the public certificate through JDK keytool, compares its SHA-256 before assembly, and refuses to overwrite an existing key. On validation failure it removes only the new file exclusively created by that invocation. The module's debug signing configuration binds to this explicit path and requires an existing file; GitHub Actions fails closed when the path is absent. Local development retains its existing default signing path when the CI variable is absent. The final APK certificate gate remains unchanged and strict.

This resolves path ambiguity and also detects an incorrect secret's certificate before building. It does not assume the secret's actual bytes match the source key until the new CI prebuild validation proves that. No private source key or repository secret was read by this worker, no signing identity was rotated, and no dependency/product behavior or version was changed.
