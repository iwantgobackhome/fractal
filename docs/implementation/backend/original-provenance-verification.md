## Limits and integration work

No Android/Electron reader source or UI was changed, and no branch was merged. Root/C/D own adoption of the optional fields and stale-anchor display behavior. Untagged historical geometry intentionally retains existing placement with unknown frame/source identity. The backend never translates old boxes or annotates translated text positions.

Source-region boxes are bounding envelopes for the validated selected original range, with accepted approximate font metrics; they are not exact glyph outlines, model claim verification, OCR, arbitrary figure localization or native hit-test proof. Unsupported unit quads produce page-only citations. A failed generation has no completed `AiAnswer`; its retained context still lets readers check the anchor against the current PDF/layout. Disconnection/cancel/error/restart behavior remains covered by the accepted foundation tests.

Native Android API35 crop/rotation equivalence remains unverified. Current official [SelectionBoundary documentation](https://developer.android.com/reference/android/graphics/pdf/models/selection/SelectionBoundary) specifies top-left points and native text-stream indexes; this does not establish equality with PDF.js original UTF16 offsets or unrotated crop geometry. The accepted independent E MuPDF/rendered evidence remains the broader external checkpoint; this followup proves the new declared coordinate conversion against actual PDF.js viewports and HTTP payloads, without claiming new native-device or interactive platform acceptance.
