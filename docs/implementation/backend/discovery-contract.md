# Discovery and related papers contract

All JSON routes retain the hub `{data:...}` envelope and existing local/paired guards. Additions are optional for old feed/library/related payloads. Shared schemas/types: `contracts/publication.ts`, `feed.ts`, `related.ts`, `library.ts`.

`PublicationMetadata = {year:number|null,venue:string|null,publicationKind:'journal'|'conference'|'preprint'|'other'|'unknown',publicationDate:string|null,oaAvailability:'open'|'closed'|'unknown',oaPdfUrl:string|null,sources?:('openAlex'|'crossref'|'semanticScholar'|'arxiv'|'huggingFace'|'user')[]}`. It is the optional `publication` field on FeedItem, RelatedPaper and LibraryRecord; source/provider identifies where it came from. Unknown fields remain null/unknown. FeedItem retains legacy `publishedAt` for sorting; `dateBasis:'observed'` means it is the observation time for that snapshot, NOT a claimed publication date, and `publication.publicationDate` remains null. New sources report `dateBasis:'publication'` when known. News and old sources keep their existing shapes. Feed settings add optional `sources.openAlex` and `sources.crossref`, enabled by default when omitted; all existing source/custom/topic switches remain.

`GET /api/papers/:key/related` keeps `{items,source:'semanticScholar'|'openAlex',fetchedAt:string|null}` and adds optional `status:'ready'|'partial'|'stale'|'unavailable'`, `providerStatus:PublicationProviderStatus[]`. A status is `{provider:'semanticScholar'|'openAlex'|'crossref',state:'ok'|'not_found'|'rate_limited'|'timeout'|'error'|'auth_required'|'budget_exhausted',message?,httpStatus?,retryAt?}`. A new related item includes `provider`, `publication` and `relations` while retaining legacy `relation`. `cites` is a reference cited by the target paper; `citedBy` is a paper citing the target; `similar` is a recommendation. Dedup preserves multiple relation types. Stale results retain actual cache fetchedAt, report provider failures and recompute current catalog membership (`inLibrary` retains its legacy record-exists meaning; explicit saved state is `LibraryRecord.saved`). Unavailable results have no items, null fetchedAt and provider failures; `source` identifies the last attempted provider for legacy compatibility, not a success claim.

`POST /api/feed/items/:id/save` explicitly saves metadata, without acquiring/downloading a PDF, and returns `{paperKey,record:LibraryRecord,hasPdf:boolean}` (old paperKey field retained). `POST /api/library/bookmarks` saves a related/discovered card with body `{title,authors:string[],url:httpsURL,doi?,arxivId?,abstract?,publication?}` and the same result. New catalog keys use `pub-<sha256 of normalized identity>`; normalized DOI/arXiv matches, or an unambiguous ordered-title match with compatible known authors/year, reuse an existing library record. Contradictory reported DOI/arXiv IDs remain separate even with equal titles. No-ID key input also includes normalized authors/year, so contradictory same-title/URL records retain separate stable keys; exact prior bookmark key replay preserves user edits. Saved state is explicit and unknown publication fields stay unknown. Existing POST `/api/library/metadata`, PATCH library save/read state and sync contracts remain supported.

`POST /api/library/:key/pdf` takes `application/pdf` bytes (50 MiB maximum) selected by the user and returns `{paperKey,record,hasPdf:true,paper}` after local extraction. It never fetches metadata/PDF over the network. The catalog key remains stable; discovered metadata, saved state, memberships, history and annotations are retained. Repeating identical PDF bytes is idempotent, including across restart. A different PDF on an already linked record is rejected (409 SOURCE_CHANGED); a detected conflicting explicit document-metadata DOI/arXiv ID is rejected before saving. If the PDF has no usable identifier, association follows the user's explicit target choice; it is not claimed as a verified bibliographic match. Existing safe legacy catalog keys can be linked through this explicit route only. Linked Paper carries `sourceKind:publication`, `catalogKey:paperKey`, null arxivId/version, and the actual immutable PDF hash. Keys must pass unchanged assertSafeKey and must not be reserved arXiv or pdf-reader identities; ordinary PDF/arXiv identity validation is retained. The route confirms an existing catalog and never derives a filesystem path from a publication URL. Only explicit own-document metadata identifiers establish conflict evidence (dedicated identifier/XMP or a complete DOI/arXiv Subject); incidental/cited identifiers in visible page text do not. Detected own-document DOI/arXiv conflicts and reserved identities return 400 INVALID_INPUT. A concurrent different PDF returns 409 BUSY. Identical concurrent uploads share work; extraction finishes before the transaction, and transaction failure leaves existing catalog metadata untouched. Blob bytes from a failed transaction may be unreferenced until normal cleanup; no old blob or user row is discarded.

Optional secrets are hub environment-only: `OPENALEX_API_KEY` (Bearer), existing `SEMANTIC_SCHOLAR_API_KEY` (x-api-key), `FRACTAL_CONTACT_EMAIL` (Crossref polite pool). They are not serialized to settings/feed/sync/logs. Anonymous/free service access remains usable; provider auth/rate/budget outages are explicit. Provider requests use allowlisted HTTPS API origins, reject redirects, bounded response sizes, independent deadlines and per-provider throttles; 429 cooldowns honor bounded Retry-After without spinning/retrying in the same request.

Feed provider `source` values add `openAlex` and `crossref`; comma-separated provenance is retained after cross-provider dedup. `FeedItem.topicIds?:string[]` preserves followed-topic association for scholarly searches as well as existing news. `FeedSourceStatus` optionally includes `errorCode` using the provider states above (except ok) and `retryAt` ISO timestamp. Existing state remains `ok|cached|error|disabled`; partial search success returns actual items plus error status rather than an invented complete-success state.

Discovery builds at most 12 OpenAlex work queries and four Crossref bibliographic searches from category English names, custom queries, followed topics, interests and authors, limited to the previous 31 days and 15 works/query. Followed authors use Crossref query.author or an OpenAlex author-ID works filter after a bounded author-name lookup (max one additional lookup per selected query); missing/ambiguous author names report not_found rather than claim a unique author. No obsolete provider work-type filter is required; current explicit conference-paper and primary conference/journal locations are recognized. Unknown dates remain unknown in metadata. Anonymous quotas can be exhausted by large interest lists/refreshes; the response reports this, and optional free keys increase the OpenAlex budget. No PDF, paid endpoint or AI call is required by these searches.

Related cache v13 is additive (`related_provider_cache`, primary key provider+normalized identity+title+known authors/year); prior tables/rows remain intact. Successful complete provider snapshots last seven days; a fresh empty first-provider snapshot continues to fallback without a new network request, and stale useful results survive an empty terminal fallback; provider errors never overwrite good data. In-flight identical identities share extraction/query work. DOI lookup 404/missing or contradictory ID triggers conservative exact normalized-sequence title search with compatible known author/year evidence; multiple remaining candidates are unresolved, with no invented arXiv DOI and no reordered bag-of-words identity. Semantic Scholar graph references/citations precede recommendation lookup; unavailable optional recommendation endpoint returns useful partial graph results. OpenAlex returns separately bounded related/reference batches and citing papers. Discovery/related/Crossref-ingest requests are serialized per provider at a conservative 1 request/second, max 16 queued, 5 seconds/request including queue wait, 5 MB response limit and a new 9-second operation budget for each related provider. 429 sets a 1-60 second cooldown (Retry-After); exhausted OpenAlex daily budget uses its reset header, max 24 hours, with no retry loop. A caller's abort detaches from shared work; service shutdown cancels and drains it before SQLite closes.

`lastReadAt` plus `readProgress` in one PATCH/sync mutation is one read event. Older or equal UTC instants retain the current event together, comparing equivalent ISO spellings and preserving sub-millisecond fractional precision; a progress-only edit remains supported. Existing sync CAS/idempotency receipts and annotation semantics are unchanged, including rejection of creating annotations against a metadata-only catalog with no reader.
