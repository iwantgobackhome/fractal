# Original PDF selection geometry

Contract published for backend B / Android D / desktop C. Source types and Zod schemas are in `packages/shared/src/contracts/pdf-text.ts`. Current extraction version is **`pdfjs6-original-advances-v1`** (`TEXT_LAYOUT_VERSION` in hub `pdf/text-layout.ts`); changing extraction semantics requires a version change.

`GET /api/papers/:key/text-layout?page=N` requires one positive integer physical page (one-based). Existing local/paired request guards apply: loopback GET uses existing read access, remote pull requires a paired device Bearer token. Unknown paper: 404; malformed page: 400. A successful extraction or cached page returns HTTP 200 with **`{data: PdfTextLayout}`**, the existing hub JSON envelope, with no additional `{layout: ...}` wrapper. `status: unavailable` inside `data` also returns 200 so clients can retain its actionable reason. Errors use the existing `{error:AppError}` envelope; queue saturation returns 503/BUSY and is retryable. No SSE/events, remote acquisition, OCR, or mutation of source blocks/annotations is involved.

Ready response: `{status:'ready',paperKey,pdfSha256,extractionVersion,pageCount,page:PdfTextPage}`. The SHA-256 is computed from actual local PDF bytes, not bibliographic metadata. Cache identity is `(pdfSha256,extractionVersion,physicalPage)`, independent of paper key; clients persist the same identity beside their downloaded PDF and verify the hash before hit testing. Every request revalidates current bytes. `unavailable` has `reason: no_pdf|too_large|invalid_pdf|page_out_of_range|timeout|page_limit`, `message`, `retryable` and optional hash/count. `no_pdf` means acquire/import the paper through the existing ingestion flow first; this endpoint never downloads it.

Page fields: `page`, `cropBox:[x0,y0,x1,y1]` in unrotated PDF user space, `width`, `height` (crop dimensions in PDF user-space points), `userUnit` (multiply by this to get physical points), `rotation:0|90|180|270`, original Unicode `text`, `runs`, sorted unique legal `boundaries`, `coverage:text|partial|no_text`, `issues:string[]`, `readingOrder:'geometric-heuristic'`. Page text uses PDF.js `disableNormalization:true`; its UTF-16 offsets refer to exactly this string. Runs retain original item strings with one generated newline separator between runs. No text is normalized or dehyphenated. `Block.pageOrdinal` remains an ordinal within a page and is never a physical page or selection offset.

A run has inclusive `start`, exclusive `end`, `quad` or null, `direction:ltr|rtl|ttb`, `granularity:glyph-advance|run`, `confidence:approximate|unsupported`, `units` and `words`. A unit/word is `{start,end,quad}`. Quads contain four `[x,y]` points in top-left normalized **unrotated crop-relative** coordinates: baseline-start descent, baseline-start ascent, baseline-end ascent, baseline-end descent. They can extend outside the crop; clip drawing/hits to the page. Apply intrinsic page rotation exactly once before viewport scaling: 90° maps `(x,y)` to `(1-y,x)`, 180° to `(1-x,1-y)`, 270° to `(y,1-x)`. Arbitrarily rotated text uses its quad, not an axis-aligned paragraph box. Reading order is estimated in displayed page coordinates, including supported two-column bands; complex tables/equations can remain ambiguous.

Legal endpoints include run edges, generated separators, and glyph groups merged to Unicode grapheme boundaries. Ligature glyph Unicode sequences remain indivisible even when they contain several UTF-16 code units. For glyph advances, PDF.js operator Unicode/width data supply proportional distances; total advances are scaled to the actual text item width. These are approximate font advance/ascent/descent envelopes, **not exact painted glyph outlines**: internal TJ kerning, character spacing, font substitutions, missing font metrics and combining-mark placement can differ. Ambiguous/missing metrics, RTL or vertical text use indivisible run boundaries with an explicit issue. Do not subdivide such a run uniformly. Word boundaries are emitted only where they coincide with legal glyph/grapheme edges. A client should snap endpoints to `boundaries`, return `text.slice(start,end)`, and draw the covered unit quads (clip first/last at their legal boundaries). Generated separators have no quad.

The extractor matches original runs against per-font, source-order operator glyph streams, rather than a per-font Unicode dictionary. Thus an actual `fi` ligature and ordinary `f` plus `i` in the same font have different legal endpoints. If text items cannot be matched to whole operator glyphs (including synthesized whitespace), it falls back to run edges. This remains an approximate association; unusual PDF.js item reordering or ambiguous repeated operator text can prevent reliable internal boundaries. Missing styles/transforms retain the original string and readable neighboring runs; null quads and partial coverage identify unavailable geometry. Combining marks are grouped safely but their ink can extend beyond the font envelope, as the rendered fixture demonstrates.

Limits: 50 MiB PDF bytes, 3000 document pages, 200000 page operators/glyphs per font, 50000 page UTF-16 characters, 10000 runs, 30-second cooperative extraction deadline. At most two pages extract and four distinct requests wait; duplicates join their existing job even when full. Closing a client does not cancel cached work. Service shutdown drains admitted jobs before SQLite closes. Timeouts/failures are not cached and can retry; there is no sticky failed job state. Operator metrics unavailable yield partial run geometry. The deadline destroys the PDF.js loading task; it is not a separate process or hard CPU preemption guarantee. Persistent cache holds at most 512 pages/128 MiB by last access. Eviction affects only derived positions, which can be regenerated. Request work uses captured immutable bytes; if a PDF changes during extraction, that response is still identified by its captured hash and clients must compare it against their own PDF.

SQLite migration 12 adds only `pdf_text_pages(pdf_hash,version,page,data,size,accessed_at)` with composite primary key `(pdf_hash,version,page)`. All old PDFs, blocks, translations, annotations, library metadata and conversations remain intact. Existing PDFs are extracted on demand; new extraction versions never reuse old cached geometry. Cached pages are pull-only derived data, not annotation sync records. No sync cursor advances during extraction. Identical PDFs shared by two paper keys reuse geometry while responses retain the requested paper key. Metadata-only library records are recognized and return `no_pdf`, even before a reader Paper record exists.
