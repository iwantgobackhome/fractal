# W2-H1 — Android reader app

## Summary

Built `:app`, `:data`, `:sync`, and `:pdf` on the H2 design and ink modules. The app pairs by bundled ML Kit QR scanning or URL and code, stores the bearer token with an Android Keystore AES-GCM key, keeps a Room library and annotation store, caches checksum-verified PDFs, and synchronizes with WorkManager. The reader renders vertical PDF pages with ink, region highlights, memos, notes, and a hub-backed question panel. Compact and expanded layouts were exercised on the emulator. The H2 toolbar now shows the current colour and four recent colours, with 24dp undo, redo, and plus glyphs in 48dp targets.

## Module map and libraries

| Module | Responsibility |
| --- | --- |
| `:app` | Compose Connect, Library, Reader, Notes/Questions, Settings; CameraX QR analyzer |
| `:data` | Room records, annotation LWW/cursor logic, SHA-256 PDF cache |
| `:sync` | Pairing, bearer HTTP, Range download, SSE, WorkManager pull/push |
| `:pdf` | Platform `PdfRenderer`, 80 MB bitmap LRU, API 35 text geometry |
| `:design`, `:ink` | Existing tokens/theme and S Pen ink engine |

Android Gradle Plugin 8.9.1; Kotlin 2.1.0; Compose BOM 2025.04.01; Room 2.7.2; WorkManager 2.10.2; CameraX 1.4.2; bundled ML Kit barcode 17.3.0; OkHttp 4.12.0; kotlinx.serialization 1.8.0. Libraries are Apache 2.0 or similarly permissive.

## Hub changes needed

- `POST /api/papers/:key/ask` has no image input for a lasso crop. The handwriting-to-question action stays hidden; questions use text only.
- There is no per-page ink endpoint. The app uses `/api/sync/pull` and filters annotations locally; this works but fetches all changed annotations.
- The hub's PDF Range route does not evaluate `If-Range`. The Android downloader verifies the final SHA-256 before committing, so stale partial bytes cannot become a cached PDF.

## Android limits and real tablet checks

- API 35 `PdfRenderer` exposes text geometry. On API 33, long-press creates a region highlight without extracted text. Check actual text selection on an API 35 Galaxy Tab.
- Dark PDF rendering uses a simple inverted luminance filter; colour figures and sepia PDF recolouring need visual review on the device.
- AI provider listing and SSE citation parsing are wired, but the emulator run did not send an AI question. Verify model choice, streamed answer, and `[p.N]` jumps against a signed-in hub.
- Check S Pen pressure, side-button eraser, palm rejection, toolbar collapse, split-screen resizing, and long sessions on the real Galaxy Tab. The emulator uses injected stylus swipes and does not reproduce Samsung digitizer behaviour.
