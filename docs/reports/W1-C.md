# W1-C: AI providers

## Summary

Added Codex and Claude provider adapters, selection and settings, persistent usage totals, streamed AI routes, a naive library search interface, and a compatibility adapter for the existing chat and translation endpoints. The Codex adapter reuses the existing isolated app-server question path and login/logout session. Claude uses the installed subscription CLI in headless, tool-free, nonpersistent mode. Added Zod contracts and fake-process/route tests.

## Endpoints

- `GET /api/ai/providers`: provider status, models, settings.
- `PUT /api/ai/settings`: default and per-feature provider/model/effort.
- `GET /api/ai/usage`: UTC day/provider/model totals and best-effort limits.
- `POST /api/papers/:key/ask`: SSE answer with `[p.N]` citation.
- `POST /api/papers/:key/explain`: SSE text/figure/table/equation explanation and equation LaTeX field.
- `POST /api/library/ask`: SSE answer grounded in injected `LibrarySearch` hits.
- `POST /api/papers/:key/glossary`: cached SSE term definitions with first page.

## Decisions

- Codex retains its app-owned `.codex-home` for the hub, so its HTTP provider status is `signed_out` until the app's existing login flow completes. The system Codex CLI has a separate active ChatGPT login; its real prompt above proves that installation, without reading or copying credentials. A Codex HTTP ask was therefore not available during this run.
- Claude flags were checked against installed `claude --help`. `--tools ""`, `--safe-mode`, `--strict-mcp-config`, and `--no-session-persistence` keep the headless request free of tools, custom hooks, MCP servers and saved sessions. Prompts go through stdin; system framing is included in the stdin text.
- The installed CLI has no documented text-mode flag for an inline image on stdin. Explain validates the optional crop and uses extracted page text and caller-supplied surrounding text. It does not send PNG pixels to either provider.
- The app-server schema generated by installed Codex 0.159.0 confirms `turn/start.effort`; the adapter passes the selected effort through that field. Claude uses its documented `--effort` flag.
- Usage counts are recorded per request in `ai-usage.json`; unavailable token counts are `null`. Claude currently reports no machine-readable subscription limit through the checked CLI interface, so its `limits` value is `null`.
- The library search is a small in-memory keyword ranker over current blocks. Glossary cache is in memory, keyed by paper content and selected model.

## Integrator notes and known gaps

- Replace `InMemoryLibrarySearch` with B's FTS5 `searchLibrary` implementation in `main.ts`; the route already accepts the `LibrarySearch` interface.
- B can replace `JsonSettingsStore` and `JsonUsageStore` with SQLite implementations without changing route or registry contracts.
- UI model picking and citation-link rendering belong to the UI worktree; no UI files were changed here.
- Crop pixels are not used for multimodal explanation yet. The equation `latex` field is an empty string if the model omits a recognizable math delimiter.
- The hub's Codex session must be logged in through its existing `/api/connection/login` flow before Codex HTTP asks can succeed.

## Review fixes

The coordinator identified that the first compatibility adapter replaced Codex's established translation prompts, output validation, and per-conversation thread reuse. Codex `translate`, `translatePage`, `ask`, and `forget` now call the original `CodexTranslator` methods with the original arguments. The adapter records reported usage after those calls without changing their prompts or results.

The original Korean single-paragraph and page-batch prompt builders, output schemas, and JSON validators now live in `translation/prompt.ts`. Codex imports them; Claude uses the same prompt text and validation rules. Claude paper chat passes the full paper instructions and every completed turn in role order. Tests use spies for identical Codex calls and fake Claude output to check the Korean rules, ordered history, and `INVALID_TRANSLATION` on malformed JSON.

`docs/API.md` now shows the exact nested `GET /api/ai/providers` response shape, including optional status detail and model effort fields.

Claude image input remains a known gap: with tools disabled, the CLI cannot read a crop from a file. The smallest safe follow-up is to verify that Claude's `--input-format stream-json` accepts an inline image content block, then send base64 pixels on stdin with tools still disabled and session persistence off. That path needs fake-process parsing tests and one real CLI check before it is enabled; it should not create a temporary image file.
