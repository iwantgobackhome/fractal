# Android cached PDF integrity correction

Coordinator review identified a concrete cached-byte reuse gap after the initial live native proof. The correction adds suspend `PdfCache.verified`, which hashes on `Dispatchers.IO` and evicts only the mismatched immutable SHA file. Downloader cached reuse, ReaderWorkspace actual open, and auto-download checks use that read boundary; shelf `contains` and management-only `existing` remain cheap. A mismatched partial file is removed on commit failure so explicit retry starts with fresh bytes. Room metadata, stable identity, Save/Recent intent, annotations, reader position and history are not erased by cache refusal.

Debug app/test APK build and app/sync/data unit tests pass. Native `PdfCacheIntegrityTest` changes owned fixture bytes while retaining both file size and timestamp, proves refusal/eviction, proves wrong partial removal, and then verifies normal bytes again. Native MainActivity `h_ownedCorruptCacheCannotReadOfflineAndVerifiedHubRedownloadPreservesIdentity` alters only the owned JMLR cache: offline Read never mounts the PDF surface or changes Recent; actual accepted Hub acquisition redownloads matching bytes while keeping the key/hash/unsaved state; normal and subsequent offline original reads succeed. Both tests pass (`native-cache-integrity.log`).

The corrected current product also passes native `i_exactUserCachedOriginalRemainsUsableAfterIntegrityCorrection` for the exact user 49,668,700-byte arXiv v1 original offline, plus all five acquisition Room regressions (`native-current-integrity-and-room.log`, six tests). Full cached-file hashing runs on IO at actual read/acquisition boundaries.
